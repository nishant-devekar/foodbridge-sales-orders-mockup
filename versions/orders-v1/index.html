Sales Orders /orders

Frozen snapshot orders-v1, accepted 2026-08-11. Matched against a live reference screenshot and DOM. Immutable — iterate in discovery/ and snapshot the next accepted round as orders-v2. This round is a fidelity port of the whole orders list screen on the live storefront route /orders — the table and its filters, and every control around them: the action bar, the bulk-order dropdown, the mobile footer and Smart Insights. Same structure, same classes, same edge cases, driven entirely by seed data. Nothing here calls a real API, and nothing here is imported by development/.

Scope of this round

Phase 1 covers the whole list screen — every control on it. That means the table and its filters, and also the full action bar, the bulk-order mode dropdown, the mobile sticky footer, the Smart Insights hover card, and bulk-order mode dropdown. Each is gated behind the same feature flag the live app uses.

What is not here is what sits behind those buttons. /orders is by far the largest route ported so far — about 13,800 lines of reachable UI against ~6,000 for each of the previous two modules — so the destinations were split into later phases. Every one of them is reachable from the list and says what it is rather than doing nothing:

  • Order creation — CreateOrderDrawer (4,832 lines, 32k closure) and BulkOrderDrawer. The drawer alone is larger than the staff and inventory modules combined.
  • Order detail and amendment — OrderCartModal, OrderFulfillmentMetadata, OrderEditDrawer, SubOrderDrawer.
  • Reporting and follow-up — DemandReportDrawer, OrderForecastDrawer, OrderReminderModal, CreateDeliveryModal.

Known divergences from the live app

Recorded deliberately rather than papered over:
  • Three of the four tabs are unreachable in the live app. OrderTabView is the only caller of setActiveTab and it is commented out, so activeTab is permanently "TabOrders". Batch Management, Production and Reports — plus the CreateBatch and ProxyOrderSelection drawers, whose triggers are also commented out — can never render. Not ported, and worth raising as a live defect.
  • Order dates are stored as offsets, not absolute dates, so the date-range filter stays meaningful however long after freezing this is opened.
  • Filtering and paging run client-side here. Live they are server-side query parameters on getAllOrders; the mock reproduces the same contract against seed data.
  • The expanded row is a summary placeholder. Live it renders OrderFulfillmentMetadata (685 lines) — deferred with the rest of the detail phase.
  • Feature flags match the reference tenant. The action bar shows the four buttons that tenant enables — Create Delivery, Create Order, Bulk Orders, Follow-up Reminders. Forecast Orders, Generate Demand, Download All and the Allocation Status column are all supported by the ported code but switched off in the seed, because the reference screenshot shows them off.
  • Order status values come from the reference screenshot — Delivered, Dispatch Created, Skipped, Inprogress — but the transitions between them are inferred, since a screenshot cannot show a workflow.
  • The Google Sheet subsystem is dropped. Live, /orders carries an export/sync toolbar with a current-vs-history mode picker and an embedded sheet view that replaces the table. Excluded from this prototype by decision — it was built and then removed, so the omission is deliberate and recorded, not an oversight.
  • Smart Insights runs on seeded figures. Live the rules derive from the dispatch, delivery and return records themselves; those record sets are a later phase, so the seed carries the derived numbers and the rules run against them unchanged — same order, same thresholds, same copy, same three-item cap.
  • createDelivery defaults differently from its comment. The live code comments “defaults to shown” but checks === true, so the button is actually hidden unless explicitly enabled. Reproduced as-is.
  • The sidebar menu tree is an assumption, carried over from the staff module’s screenshot of the same tenant. The tenant’s real storefrontMenus is authoritative.
